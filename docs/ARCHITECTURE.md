# Architecture

The desktop shell is C#/.NET 10 WPF using the native Fluent theme, standard Windows file/folder dialogs, virtualized DataGrids, and Windows MediaElement playback. Application state uses transactional SQLite plus atomic JSON manifests. Source media is linked by default; copying is explicit.

`Store` owns workspace pointers, media metadata and jobs. `ModelManager` installs pinned assets into staging, verifies size/SHA256, and atomically marks installations. `Pipeline` verifies source size/mtime and model hashes, decodes the selected audio track through bundled FFmpeg, then runs the isolated speech worker. Original media is never rewritten.

The Python worker bundles CPython, NumPy, onnx-asr and CPU ONNX Runtime. Silero VAD processes at most 120 seconds of PCM at a time. Recognition regions are separately capped at 22 seconds. Parakeet weights are loaded once per job; whisper.cpp runs in CPU-only child processes per region. Each region has an atomic result checkpoint with a job/settings signature. Merge removes adjacent phrase duplication only when time intervals overlap. No speaker identity, confidence percentage or word alignment is invented.

`Processes` uses argument arrays and a Windows Job Object with kill-on-close for every child, including grandchildren. Cancellation kills the owned tree. Abrupt app exit terminates workers; subsequent launch changes unfinished jobs to Interrupted. A canceled/interrupted job can reuse matching audio/checkpoints. Changed source size/mtime or model revision prevents resume.

`Summarizer` shares a single heavy-inference gate with transcription. It launches a CPU-only, offline llama.cpp server bound to 127.0.0.1 on an ephemeral port with a random per-process API key and no web UI. Only the app's local client receives that key. The server is terminated after the summary or cancellation. Actual GGUF context metadata, native chat templates, and model tokenization govern input limits; overflow is handled with bounded map/reduce and atomic notes checkpoints. Source/context are delimited untrusted data. Generated originals and edited versions are distinct files.

Network operations exist only in explicitly requested model downloads and browser provenance links. The app has no telemetry, update polling or cloud inference. Native stdout/stderr are drained but not persistently logged; errors expose metadata and recovery steps. Model IDs/hashes, pipeline settings and source metadata remain in job manifests.

`Exporter` normalizes timestamps, CSV quoting and UTF-8 output. Subtitle output orders intervals and clips overlap. JSON always preserves canonical metadata. Source transcripts, user edits, model runs and summaries retain separate provenance.

Storage defaults to LocalAppData for app state/models/cache and `.localtranscriber` under writable workspaces for results. Read-only workspaces use a visible app-data fallback. Model moves copy and verify before switching the pointer; the previous copy is deliberately kept for manual confirmed removal.
# Dictation extension (1.1)

`Microphone` uses Windows waveform input with six 100 ms PCM16 buffers, polled by a 40 ms UI timer. Windows format conversion is allowed; supported 16/48/44.1 kHz mono formats are attempted. Samples stream to a WAV on disk. RMS is measured from actual samples for the expanding circle. Stop/reset drains returned buffers, closes the input and finalizes the WAV header; Cancel and app close preserve recordings. No always-on microphone listener is installed.

`Dictation` reuses FFprobe, the existing ASR `Pipeline.Execute`, the shared inference gate and the same verified model/runtime artifacts. Vocabulary rules are validated, snapshotted into the job, and applied with a single escaped literal regex pass, longest phrase first, with Unicode word boundaries. Raw ASR is preserved; mapped file segments become the initial edited transcript. Dictation first flattens ASR segment whitespace, then applies vocabulary replacements, then optionally processes the text through the existing authenticated CPU-only local llama server. Qwen2.5 7B-Instruct remains the default processing model; both GGUF shards are pinned and verified. Actual tokenizer budgets and output-limit failures protect against silently truncated processing. The default light-cleanup instructions require mapped vocabulary terms to survive; custom system overrides control their own treatment of content. A failed processing stage retains the mapped text with a warning.

The floating WPF window uses `WS_EX_NOACTIVATE` and handles `WM_MOUSEACTIVATE` with `MA_NOACTIVATE`. At Record, `DictationTarget` captures the foreground window, focused HWND and UI Automation element. Immediately before `SendInput`, it rechecks all three, password/editability state and held modifier keys. It never restores a changed focus or presses a submit key. All text uses Ctrl+V: rapid Unicode packets can drop characters in long single lines and do not reliably preserve paragraphs. Clipboard formats are snapshotted before replacement and restored only after field-text confirmation, guarded by clipboard sequence number. An unconfirmed paste keeps the dictation on the clipboard and retains the backup for explicit restoration. A failed/partial insertion is reported without retrying (which could duplicate text). Third-party control compatibility is a documented limitation; Copy remains available.

The first-use tutorial is an inline Help panel, persisted in backward-compatible settings only when completed. No modal startup dialog blocks the UI. Speech model/language/input/cleanup preferences and vocabulary are saved in the existing atomic settings file. `dictation/latest.json` restores the most recent completed result, while each job retains its own provenance. Settings and job schemas accept older files through defaults; older completed jobs are not changed.

## Speech processing (1.2)

Named `SpeechPrompt` profiles live in the existing settings file. The selected system text fully replaces the built-in editing instructions; a separate Markdown/plain-text constraint is appended. Light cleanup and Document structure are built-in, resettable choices; custom profiles can be saved, renamed and deleted. Profile IDs supply stable equality/hash keys while WPF selection items are edited. Recording snapshots its profile, models and vocabulary before work starts.

`Dictation.Process` is shared by new recordings and workbench reprocessing. Reprocessing always starts from the immutable raw ASR, preserves the original ASR duration, and records a new LLM duration without rerunning ASR or inserting externally. Previous `dictation.json` results are copied to `dictation-versions` before replacement. Result provenance includes normalized/raw/mapped/final text, model revisions and artifacts, prompt snapshot, format choice, vocabulary and separate stage elapsed times. Stopwatches include preparation, model verification/loading and inference; microphone recording time is excluded. Nullable timing fields keep older results readable without fabricated measurements.

Plain-text mode uses the pinned Markdig parser locally after LLM generation. Small renderer overrides retain blank lines between paragraphs, link destinations and table cell separators while removing Markdown formatting. Markdown mode preserves the generated Markdown. No extra worker, model call or network request is added.
