# Decisions and limits

1. **WPF fallback.** .NET 10.0.101 was installed; no WinUI template or usable Visual Studio instance was found. The required WinUI skill bootstrap (`winget configure -f config.yaml --accept-configuration-agreements --disable-interactivity`) produced no progress for more than two minutes in the noninteractive session and was canceled. The specification explicitly permits WPF. .NET's built-in Fluent theme supplies system/light/dark modes without a new UI dependency. [Microsoft documentation](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net90).
2. **ZIP distribution.** The self-contained WPF EXE ships with native worker directories. Downloaded large models remain external. No developer runtime is needed by the user; actual clean-machine verification is tracked separately in TEST_RESULTS.
3. **Parakeet conversion.** NVIDIA's CC-BY-4.0 V3 model is served through the pinned `istupakov/parakeet-tdt-0.6b-v3-onnx` INT8 conversion and onnx-asr 0.10.2. This is a community conversion, not an NVIDIA Windows binary. Language forcing/hints are disabled because the chosen adapter cannot enforce them. Token onsets plus VAD boundaries supply segment timing; word alignment is not claimed.
4. **One heavy model.** The queue and summary service share one semaphore. This avoids simultaneous weight loading on 16 GB laptops. The release requires AVX2 and explains that limitation before inference. Other instruction-set builds are not supplied.
5. **VAD and cleanup.** Silero ONNX is bundled under MIT. Automatic cleanup measures a short sample and applies at most +3 dB gain with limiting when justified. Enhanced is FFmpeg FFT denoise, explicitly labelled, with an A/B sample. RNNoise/DeepFilterNet and heavy enhancement are not bundled. No denoising quality claim is made without a representative benchmark.
6. **Whisper chunk isolation.** Per-region native CLI invocation supplies crash isolation, bounded memory, checkpoints and real progress. It reloads weights per region, which can be slow on long recordings. A persistent whisper library worker is the upgrade path if measured throughput is insufficient.
7. **Summary transport.** An ephemeral authenticated loopback server is used to access llama.cpp's tokenizer/chat-template APIs. It never binds to external interfaces and runs with `--offline`, zero GPU layers and operation offload disabled. Named-pipe/in-process transport is a future alternative if supported by the pinned runtime.
8. **Context.** Auto suggests 2048/4096 tokens from actual available memory; user settings cap at 8192 and are also bounded by the model's metadata. These are conservative operating limits, not advertised maximum-context guarantees. Token counting is real. Long-source map/reduce may omit details; it retains notes and warns visibly. Generated citations are validated against segment IDs; existence is not proof of semantic support.
9. **Unavailable optional providers.** Qwen3-ASR and Moonshine are explicitly unavailable. No audio-capable Windows adapter was integrated and validated, so text-only GGUF loading is not counted as speech support. Automatic diarization, word alignment, comparison highlighting and correction proposals remain unimplemented P1 features. Independent transcription runs and manual speaker labels are supported.
10. **Model imports.** Imports copy weights to owned storage and require an actual isolated CPU load/inference check. Parakeet imports use the known V3 INT8 layout. LLM imports require bounded GGUF metadata and a successful llama.cpp test. The original model licence remains the user's responsibility; generic imports do not inherit a catalogue licence. Unrecognized weight hashes receive unknown language capabilities, disabled speech language forcing and a conservative size-based RAM estimate rather than inheriting an unsupported claim from the selected profile.
11. **Resource inventory.** RAM, available memory, logical/physical CPUs, CPU name, AVX2, detected display drivers and model/cache/workspace drive free space are live Windows values. Detected display drivers do not imply a usable inference provider; GPU acceleration stays disabled. Full 16/32 GB machine benchmarking is a separate validation step.
12. **FFmpeg source location.** The Gyan release URL is mutable; the downloaded build is locked by SHA256. Future changes fail integrity verification and require an intentional lock update. Keep the verified `.tools/ffmpeg.zip` in a build cache to reproduce this exact release after the upstream URL changes.
13. **Dictation cleanup (1.1).** The user explicitly extended the initial scope to include microphone dictation, optional faithful editing, a vocabulary map and onboarding. Existing ASR/LLM workers and the inference gate are reused. Development probes found that the LFM 1.2B/2.6B/8B-A1B models could reverse or retain spoken retractions and even include example text. Qwen2.5 7B-Instruct Q4_K_M passed the selected English/French correction cases and is the cleanup default. Its two official GGUF shards and Apache licence are separately pinned; it costs more CPU time and RAM. No model is claimed to preserve arbitrary speech perfectly, so raw/mapped text stays available and cleanup remains optional.
14. **Selected-field insertion.** The floating window keeps the external app active. Focus/element identity is revalidated before insertion; changing the destination holds the result for copying. Unicode packet typing works for single lines, but dropped paragraph breaks in the separate-process WPF test. Multiline text therefore uses paste with a clipboard snapshot and field-text confirmation. Unconfirmed pastes keep a recoverable clipboard backup rather than restoring old clipboard data while a delayed paste might still read it. Direct insertion does not send/submit the field, bypass UAC, or support password/read-only fields.
15. **Compact language models (1.2).** The user requested Qwen3.5 0.8B/2B/4B and Gemma 4 E2B/E4B as downloadable choices. Q4_K_M conversions from Unsloth are pinned by repository revision, byte count and SHA256, with Apache-2.0 licence artifacts. These are text-processing entries for the existing llama.cpp adapter. Audio/vision support from the multimodal families is not advertised. Models download separately, and the catalogue UI describes capabilities and resource needs without testing-status labels.
16. **Speech prompts and timing (1.2).** A complete user system override replaces the faithful-editing default; the chosen Markdown/plain-text policy remains a separate output constraint. Shared processing removes segment whitespace before vocabulary replacement and can reapply a prompt to unchanged raw speech. Markdig handles residual Markdown in-process, preserving paragraphs, URLs and table contents. Separate wall times include each stage's preparation/model loading and generation; recording time is excluded. Original ASR timing survives workbench prompt comparisons, and earlier processed results remain saved.
17. **Single-line paste (1.2).** Removing segment newlines sends longer results through the former Unicode-packet path. Real ASR-to-field checks found dropped characters in these bursts. The existing confirmed-paste path now handles every result, with the same selection, focus, password/read-only and clipboard-sequence guards. This deletes the separate typing branch and preserves both long single lines and paragraphs.
